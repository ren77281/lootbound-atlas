## How should Lootbound achievements be verified?

Treat the live Steam achievement panel as the catalog authority, then reproduce uncertain requirements in the current game build. A fabricated condition wastes more player time than an incomplete list, so named entries should only appear after the visible catalog is captured and ambiguous triggers are tested cleanly.

## What belongs in an achievement record?

A useful record preserves enough context for another player to repeat the test. Capture both successful and unsuccessful attempts so a coincidence is not mistaken for the real trigger.

| Field | What to record |
| --- | --- |
| Catalog | Achievement name and visible description |
| Visibility | Whether Steam marks it hidden or visible |
| Version | Game build and test date |
| Trigger | Action immediately before the unlock |
| Sync | Whether the in-game notice and Steam profile updated together |

## How do you test an ambiguous condition?

Change one variable per attempt. If an unlock could depend on route, companion, inventory state, or Guardian setup, keep the other three stable. This isolates the likely cause and creates a record that remains useful when a patch changes one part of the system.

Use the [first-run guide](/guides/first-run-guide) for the same version-recording discipline when reporting a mechanic or bug.

## What is the current tracker status?

The verification framework is ready, but the per-achievement table remains withheld until it can cite the current catalog and reproducible observations. Steam Community Guides can suggest tests, but they are leads rather than automatic proof.
